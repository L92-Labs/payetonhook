# Agent platform 1.1.0

Use named capabilities and checked boundaries to make the usual safe implementation short. The portable JavaScript runtime has no runtime dependencies. TypeScript declarations accompany each entry point. Product adapters own authorization, tenancy, SQL and provider choices.

| Entry | Contract |
|---|---|
| `runtime/logging.js` | Structured levels, reserved level/timestamp/request identity fields, recursive secret redaction |
| `runtime/request.js` | Valid printable bounded request IDs; required string configuration |
| `runtime/http.js` | Cooperative cancellation, byte/deadline bounds, redirect rejection; no automatic retries |
| `runtime/task.js` | Named capability, validator, deadline, output token cap and usage |
| `runtime/query.js` | Tenant/actor/authorization-version keys, stable JSON filters, async state |
| `runtime/command.js` | Authorization, mutation, audit and enqueue in the same supplied transaction; atomic consumer claim/apply |
| `blueprints/catalog.js` | Frozen versioned definitions and digest-pinned selection validation |

## Recipes

A new query defines `createQueryKeys({tenantId, actorId, authorizationVersion})` in the product's query module. Render loading/error/empty/ready explicitly; use Studio UI `AsyncBoundary` where installed. Scope changes must not retain another principal's placeholder data.

A new AI capability defines a stable versioned name, validator, deadline and `maxOutputTokens`, then passes a cooperative provider adapter to `runTask`. Forward its signal and token cap. Streaming remains a separate product adapter. Never execute model-authored SQL without the product's existing authorization and SQL guard.

A mutation authorizes inside the same transaction as state, audit and outbox inserts. `runCommand` supplies ordering, not a database transaction implementation. D1 uses an atomic prepared batch; PostgreSQL uses a real transaction. External storage needs explicit compensation or a durable saga.

An event carries a stable ID and schema version. Claim and apply database effects atomically. Publish external effects through another outbox; never mark a receipt before a non-transactional external call and claim exactly-once delivery.

An adapter fixture exercises cancellation, deadlines, byte limits, malformed results, safe errors and cache invalidation against local servers/stores. Preserve protocol-specific behavior behind that adapter.

## Snapshot maintenance

Application snapshots include a complete SHA-256 inventory generated by cf-bootstrap. Existing checkout adoption stages files, rejects symlinks, locks writers, and replaces the snapshot through directory renames with rollback on publication failure. Readers can briefly see no snapshot between the backup and replacement renames; run adoption while checks and builds are stopped. Review snapshot diffs before updating. Keep legacy architecture exceptions tied to their original source hashes.

Run `node --test .agent-platform/tests/runtime.test.mjs` and `node .agent-platform/policy/check.mjs`. The canonical policy negative tests live in `scripts/agent-platform-tests/policy.test.mjs`. GitLob catalog selection validates a blueprint; cf-bootstrap's normal plan/provision lifecycle performs generation and deployment.

Backend rules reject provider SDK imports outside reviewed adapters. Worker
binding rules check named reads, declaration/assignment destructuring and
computed environment aliases. Python follows module-loader aliases and resolves
relative dynamic imports. These syntax checks constrain normal code paths; they
do not prove safety against arbitrary reflection. Existing debt must retain its
source hash; migrate edited bypasses instead of refreshing their baseline.
